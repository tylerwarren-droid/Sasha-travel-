## 1. Voice Pipeline — Current State & Exact Component Responsibilities

### Data flow
```
HeyGen LiveAvatar (voiceChat: false — WE own the mic pipeline)
  → AVATAR_SPEAK_STARTED  → gate mic ON   (VoiceButton drops PCM frames)
  → AVATAR_SPEAK_ENDED    → 900ms trailing timer → gate mic OFF
                          → FIRST TIME ONLY: onReadyToListen() → starts Deepgram

Deepgram (nova-3, streaming WebSocket)
  ← AudioWorklet (pcm-capture.js) → linear16 PCM @ AudioContext native sample rate
  → interim + final transcripts → onTranscript → conductor → Sasha response text
  → response text → avatar.repeat(text) → HeyGen speaks it
```

### Component responsibilities

**`frontend/app/components/SashaAvatar.tsx`** — HeyGen session lifecycle + the speak-gate authority.
- Constructs `LiveAvatarSession(token, { voiceChat: false, video_settings: { quality: 'medium', encoding: 'H264' } })`.
- Fetches HeyGen token from `tokenUrl` (default `/api/heygen/token`).
- On `SESSION_STREAM_READY`: attaches video, sets status `ready`, starts `keepAlive` interval **every 150s**, and registers speak handlers **exactly once** (guarded by `speakHandlersRegistered` — this is "BUG 3" guard; do not remove).
- `AVATAR_SPEAK_STARTED` → logs only.
- `AVATAR_SPEAK_ENDED` → clears safety timer, sets a **900ms trailing timer** → `openGate()`.
- `openGate()` → `onGate?.(false)` + `onAvatarSpeakingChange?.(false)` + `onSashaFinished?.()`, and **once only** (via `hasOpenedMicRef`) fires `onReadyToListen?.()` to start the mic.
- **Safety timer** in `speakFn`: `Math.max(1500, text.length * 65) + 900` ms — fires `openGate()` if `AVATAR_SPEAK_ENDED` never arrives.
- `speakFn(text)` → `clearAllTimers()` → `onGate?.(true)` → `onAvatarSpeakingChange?.(true)` → `avatar.repeat(text)` → set safety timer.
- `interruptFn()` → `avatar.interrupt?.()` + clear timers + close gate.
- Collects avatar transcription chunks into `avatarSpeechBufferRef` (15s rolling window) — exposed via `onAvatarSpeechBuffer` for the echo filter.
- Reconnect logic: on `SESSION_DISCONNECTED`, reconnect after 2s **unless** reason is `MAX_DURATION_REACHED` (then shows "tap to start new conversation"). On `SESSION_START_FAILED`, retry after 3s.
- Reconnects on `visibilitychange` → visible if status is `idle`.

**`frontend/app/components/VoiceButton.tsx`** — AudioWorklet PCM capture → Deepgram STT.
- Key env: `NEXT_PUBLIC_DEEPGRAM_API_KEY` (client-side).
- `micGatedRef = useRef(true)` — **starts gated**. Gate is a pure ref flag; the worklet always runs, audio is just suppressed.
- Exposes its gate setter to the parent on mount via `onSetGate` (empty-deps `useEffect` — stable). On gate→false it clears transcript, sets not-speaking, and sends Deepgram `{ type: 'Finalize' }` to flush buffered avatar speech.
- Deepgram WS params: `encoding=linear16&sample_rate=<ctx.sampleRate>&channels=1&model=nova-3&language=en-US&smart_format=true&interim_results=true&endpointing=300&utterance_end_ms=1000&vad_events=true`.
- Worklet `onmessage`: while gated, measures **RMS**; if `rms > 0.0005` → treat as user interrupt (`onInterruptRef.current?.()` + open gate immediately); else drop frame (speaker bleed). While ungated → float32→int16 → `ws.send(int16.buffer)`.
- Transcript handling: accumulates `is_final` fragments, fires only on `speech_final === true` (min length 3), with `UtteranceEnd` as fallback.
- **Echo filter:** `isEcho()` — 70% word-overlap against `avatarSpeechGetter()` discards avatar-echo transcripts.
- **Dedup:** `lastFinal`/`lastFinalAt` — same final within 5s is dropped.
- KeepAlive to Deepgram **every 8s**. **No auto-reconnect** on `ws.onclose` (intentional — see gotchas).
- StrictMode guard in `ws.onopen`: if `wsRef.current !== ws`, discard (cleanup superseded the connection).

- `voiceReady` state set by `onReadyToListen`; drives `readyToListen` → `SashaChat` → `VoiceButton` so Deepgram does **not** connect until after the avatar's first greeting.

### Known bug — echo / premature mic open
**Symptom:** Mic gate occasionally opens during avatar speech, letting Deepgram transcribe the avatar's voice → triggers a premature/spurious response.

**Mitigations currently in place (all layered, all live):**
1. `micGatedRef` — PCM frames dropped while avatar speaking.
2. 900ms trailing timer on `AVATAR_SPEAK_ENDED` (accounts for TTS tail).
3. Safety timer per `avatar.repeat()` call (catches missing `AVATAR_SPEAK_ENDED`).
4. Deepgram `Finalize` on gate-open (flushes buffered speech).
5. Echo filter — 70% word-overlap check against last spoken text.
6. `isRespondingRef` lock — blocks re-entry while conductor responds.

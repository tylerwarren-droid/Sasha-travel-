## 1. Voice pipeline — current state & exact component responsibilities

### Data flow

```
HeyGen LiveAvatar (voiceChat: false — WE own the mic pipeline)
  → AVATAR_SPEAK_STARTED → gate mic ON  (VoiceButton drops PCM frames)
  → AVATAR_SPEAK_ENDED   → 900ms trailing timer → gate mic OFF
                         → FIRST TIME ONLY: onReadyToListen() → starts Deepgram

Deepgram (nova-3, streaming WebSocket)
  ← AudioWorklet (/pcm-capture.js) → linear16 PCM at AudioContext native sample rate
  → interim + final transcripts → conductor → Sasha response text
  → response text → avatar.repeat(text) → HeyGen speaks it
```

### Component responsibilities

**`frontend/app/components/SashaAvatar.tsx`** — *HeyGen session lifecycle + the speak gate*
- Creates `LiveAvatarSession(token, { voiceChat: false, video_settings: { quality: 'medium', encoding: 'H264' } })`.
- **`speakFn(text)`**: calls `onGate(true)` + `onAvatarSpeakingChange(true)` → `avatar.repeat(text)` → sets a **safety timer** of `Math.max(1500, text.length * 65) + 900` ms that force-opens the gate if `AVATAR_SPEAK_ENDED` never fires.
- **`interruptFn()`**: `avatar.interrupt()` + clears timers + opens gate.
- **`AVATAR_SPEAK_ENDED`** → clears safety timer → **900ms trailing timer** → `openGate()`.
- **`openGate()`** → `onGate(false)` + `onAvatarSpeakingChange(false)` + `onSashaFinished()`; **first call only** (guarded by `hasOpenedMicRef`) fires `onReadyToListen()` to start Deepgram.
- Speak handlers registered **exactly once per avatar instance** (guarded by `speakHandlersRegistered` — this is "BUG 3" guard, do not remove).
- `keepAliveTimerRef` → `avatar.keepAlive()` every **150s**.
- Maintains a **15s rolling avatar speech buffer** (`avatarSpeechBufferRef`) exposed via `onAvatarSpeechBuffer` — used by the echo filter.
- Reconnect on `SESSION_DISCONNECTED` unless reason is `MAX_DURATION_REACHED` (shows "tap to start a new conversation"). Reconnect guarded by `isReconnecting` + `isMountedRef`.
- Re-inits on `visibilitychange` → visible when status is `idle`.

**`frontend/app/components/VoiceButton.tsx`** — *AudioWorklet PCM capture → Deepgram STT*
- Loads `/pcm-capture.js` worklet; pipes mic → `ws.send(int16.buffer)`.
- **`micGatedRef = useRef(true)`** — starts gated. Gate is a **pure ref flag**, no audio-graph teardown.
- **While gated:** measures RMS per frame. If `rms > 0.0005` → treats as user interrupt → calls `onInterrupt()` and opens the gate immediately (`micGatedRef.current = false`). Otherwise drops the frame (speaker bleed).
- **While ungated:** converts float32 → int16 PCM → sends to Deepgram.
- **Gate setter** exposed to parent via `onSetGate` on mount (empty-deps `useEffect`). On gate-open it clears `transcriptRef` and sends `{ type: 'Finalize' }` to Deepgram to flush buffered avatar speech.
- **Echo filter:** `isEcho()` — normalizes words, computes overlap against `avatarSpeechGetter()`; if ≥70% overlap, discards the transcript.
- **Dedup:** `lastFinal` / `lastFinalAt` — drops identical finals within 5s.
- Transcript assembly: accumulates `is_final` fragments, fires on `speech_final === true` (≥3 chars) OR `UtteranceEnd` fallback.
- **Deepgram WS URL params:** `encoding=linear16&sample_rate=<ctx.sampleRate>&channels=1&model=nova-3&language=en-US&smart_format=true&interim_results=true&endpointing=300&utterance_end_ms=1000&vad_events=true`.
- KeepAlive every 8s. **No auto-reconnect on close** (intentional — see Gotchas).
- StrictMode race guard in `ws.onopen`: if `wsRef.current !== ws`, discard.

**`frontend/app/vietnam/page.tsx`** — *Orchestration / wiring*
- `handleSetGate` + `handleGate` are **stable `useCallback`s with empty deps** (critical — see Gotchas #3).
- `voiceReady` state set by `onReadyToListen` → drives `readyToListen` prop down to `VoiceButton` so Deepgram won't connect until the avatar finishes its first greeting.
- `isRespondingRef` lock — blocks transcript processing while Sasha is mid-response (`handleSashaResponse` acquires, `handleSashaFinished` releases).
- `lastRepeatTextRef` holds the last spoken text; passed as `avatarSpeechGetter` for echo filtering.
- **Tap-to-start overlay** gates all audio init behind a user gesture (`started` state) — required for browser autoplay/AudioContext.
- Fetches initial photos from Railway `/api/photos/search`; rotates every 5s; conductor can replace per-turn via `onPhotos`.

**Status:** Pipeline is **working** end-to-end. The remaining issue is echo (see §2).

### Known bug: echo / premature mic open

**Symptom:** Mic gate occasionally opens during avatar speech, causing Deepgram to transcribe the avatar's own voice and trigger a premature/false response.

**Mitigations currently in place (6):**
1. `micGatedRef` gate — PCM frames dropped while avatar speaking.
2. 900ms trailing timer on `AVATAR_SPEAK_ENDED` — accounts for TTS tail.
3. Per-`repeat()` safety timer — catches missing `AVATAR_SPEAK_ENDED` events.
4. Deepgram `Finalize` on gate-open — flushes buffered speech.
5. Echo filter — 70% word-overlap check vs. last spoken text.
6. `isRespondingRef` lock — blocks re-entry while conductor responds.

**Status:** HeyGen support reviewed the source (the repo was made public specifically for this). `AVATAR_SPEAK_STARTED` / `AVATAR_SPEAK_ENDED` confirmed firing correctly in console; gate confirmed working (`[GATE] set to true/false`). **Awaiting HeyGen's diagnosis.** Their fix likely concerns event timing or a `voiceChat: false` edge case — apply whatever they recommend directly to `SashaAvatar.tsx`.

## 0. TL;DR — Read This First

This is a voice-driven AI travel concierge. A HeyGen video avatar ("Sasha") speaks responses; the user talks back through a Deepgram speech-to-text pipeline; a FastAPI backend routes each message through a **Conductor** that fires up to 23 specialist agents in parallel and merges their replies.

## 1. Voice Pipeline — Current State & Exact Component Responsibilities

### High-level flow
```
HeyGen LiveAvatar (voiceChat: false — WE own the mic)
  → AVATAR_SPEAK_STARTED → gate mic ON  (PCM frames dropped)
  → AVATAR_SPEAK_ENDED   → 900ms trailing timer → gate mic OFF
                         → first time only: onReadyToListen() → Deepgram connects

Deepgram (nova-3, streaming WS)
  ← AudioWorklet (pcm-capture.js) → linear16 PCM @ AudioContext native sample rate
  → interim + final transcripts → conductor → Sasha response text
  → avatar.repeat(text) → HeyGen speaks it
```

### Component responsibilities (exact)

**`frontend/app/components/SashaAvatar.tsx`** — HeyGen session lifecycle owner
- Creates `LiveAvatarSession(token, { voiceChat: false, video_settings: { quality: 'medium', encoding: 'H264' } })`.
- **`speakFn(text)`** (exposed to parent via `onAvatarReady`): calls `onGate?.(true)` + `onAvatarSpeakingChange?.(true)`, then `avatar.repeat(text)`. Sets a **safety timer** = `Math.max(1500, text.length * 65) + 900` ms that force-fires `openGate()` if `AVATAR_SPEAK_ENDED` never arrives.
- **`interruptFn()`**: `avatar.interrupt?.()` + clears timers + opens gate.
- **`openGate()`**: calls `onGate?.(false)`, `onAvatarSpeakingChange?.(false)`, `onSashaFinished?.()`. **First call ever** also fires `onReadyToListen?.()` (guarded by `hasOpenedMicRef`) — this is what first connects Deepgram.
- **Event handlers** (registered exactly once per avatar instance, guarded by `speakHandlersRegistered`):
  - `AVATAR_SPEAK_STARTED` → logs only.
  - `AVATAR_SPEAK_ENDED` → clears safety timer, sets **900ms trailing timer** → `openGate()`.
  - `SESSION_STOPPED` / `SESSION_DISCONNECTED` → clears timers, opens gate, fires `onSashaFinished`.
  - Maintains a **15-second rolling avatar-speech buffer** (`avatarSpeechBufferRef`) from `AVATAR_TRANSCRIPTION_CHUNK` / `AVATAR_TRANSCRIPTION` events; exposed via `onAvatarSpeechBuffer` for echo detection.
- **`keepAlive()`** every **150s** (note: `keepAlive`, NOT `ping`).
- **Reconnect:** on `SESSION_DISCONNECTED` retries after 2s **unless** reason is `MAX_DURATION_REACHED` (shows "tap to start new conversation"). On `SESSION_START_FAILED` retries after 3s. Guarded by `isReconnecting` + `isMountedRef`.
- **Connection quality:** downgrades video to `low` quality on `BAD`.

**`frontend/app/components/VoiceButton.tsx`** — mic capture + Deepgram STT
- Uses AudioWorklet `/pcm-capture.js`. **`micGatedRef = useRef(true)`** — starts gated.
- Deepgram WS params: `encoding=linear16&sample_rate={ctx.sampleRate}&channels=1&model=nova-3&language=en-US&smart_format=true&interim_results=true&endpointing=300&utterance_end_ms=1000&vad_events=true`.
- **While gated:** measures RMS on each frame. If `rms > 0.0005` → treats as user interrupt → calls `onInterruptRef.current?.()` and opens gate immediately. Otherwise drops the frame (speaker bleed).
- **While ungated:** float32 → int16 PCM → `ws.send(int16.buffer)`.
- **Gate setter** (exposed to parent via `onSetGate`, registered on mount with empty deps): sets `micGatedRef`; on gate-OFF, clears transcript and sends Deepgram `{ type: 'Finalize' }` to flush buffered avatar speech.
- **Transcript assembly:** accumulates `is_final` fragments, fires only when `speech_final === true` AND length ≥ 3. `UtteranceEnd` is a fallback path.
- **Echo filter:** `isEcho()` discards a transcript if ≥70% of its words overlap with `avatarSpeechGetter?.()`.
- **Dedup:** identical final within 5s is dropped (`lastFinal` / `lastFinalAt`).
- **KeepAlive** every 8s. **No auto-reconnect** on close (deliberate).
- StrictMode guard in `ws.onopen`: if `wsRef.current !== ws`, discards (cleanup superseded it).

**`frontend/app/vietnam/page.tsx`** — orchestration / glue
- Holds `gateRef`; `handleSetGate` and `handleGate` are **stable `useCallback`s with empty deps** (critical — see gotchas).
- `voiceReady` state set by `onReadyToListen` → drives `readyToListen` prop → triggers Deepgram `connect()` only after avatar's first greeting.
- `isRespondingRef` lock — blocks transcript processing while Sasha is mid-response.
- `started` state gates the entire avatar/audio init behind a tap-to-start overlay (browser autoplay requirement).
- Fetches initial background photos from `sasha-travel-production.up.railway.app/api/photos/search`; photos updated per-turn via `onPhotos`.
- Renders a 4-tab right column: Chat / Itinerary / Prefs / Trips. Uses hardcoded `DEMO_USER` (no auth).

### Known bug — echo / premature mic open
**Symptom:** The mic gate occasionally opens during avatar speech, letting Deepgram transcribe the avatar's own voice and trigger a premature/spurious response.

**Mitigations currently in place (6 layers):**
1. `micGatedRef` gate — PCM frames dropped while avatar speaking.
2. 900ms trailing timer on `AVATAR_SPEAK_ENDED` — covers TTS tail.
3. Per-`repeat()` safety timer — catches cases where `AVATAR_SPEAK_ENDED` never fires.
4. Deepgram `Finalize` on gate-open — flushes buffered speech.
5. Echo filter — 70% word-overlap discard against last spoken text / rolling buffer.
6. `isRespondingRef` lock — blocks re-entry while conductor responds.

**Status:** `AVATAR_SPEAK_STARTED` / `AVATAR_SPEAK_ENDED` confirmed firing in console. Gate confirmed toggling (`[GATE] set to true/false`). HeyGen support reviewed the source (this is why the repo is currently public) — **awaiting their diagnosis.** Their fix will likely touch event timing or a `voiceChat: false` edge case → apply to `SashaAvatar.tsx`.

### Conductor (`backend/app/services/conductor.py`)

**Flow (`conduct()`):**
1. Loads `conductor.general` + `conductor.merge` prompts via `get_prompt_async` (TTL-cached, falls back to static).
2. Applies client persona name swap if `client_config.persona_name != "Sasha"`.
3. **`classify_intents()`** — pure **keyword matching** (NOT an LLM call, despite the `INTENT_CLASSIFIER_PROMPT` text being present in the file — that prompt is currently unused/vestigial). Builds an intent list from large keyword arrays.
4. Fires all matched agents in **parallel** via `asyncio.gather`, each wrapped in `run_with_timeout` (**30s** timeout).
5. Collects results: `foto` contributes photos (no speech); others contribute `response` text + `tools_used`.
6. **Merge:** 0 results → fallback line; 1 result → return as-is; 2+ results → Sonnet merge call using `conductor.merge` prompt.
7. Returns `{ response, intents, photos, tools_used, messages }`.

**Special dispatch rules in `classify_intents`:**
- `golf` match also auto-appends `foto`.
- `restaurant` only fires when a topic word AND an action word are both present (or if history already established restaurant intent) — prevents firing on casual food mentions.
- `foto` auto-added on visual cue words.
- `smart_sasha` requires both a planning phrase AND a travel noun.

Mount facts used throughout:
- `backend/app/main.py` includes 15 routers: search, bookings, conversation, voice, heygen_chat, foto, conductor, ideas, cards, voice_conductor, payments, chats, trips, `booking_signer.routes` (/api/booking/*, which itself includes ~35 sub-routers and `products/routes.py`), and `app.agent.sasha` (/api/agent/*, which includes `agapi/activity.py`). **Not included: `app/api/golf.py`. Not added: `app/middleware/currency.py`.**
- Agent tool set: `agapi/v0.py` TOOLS = 18 own + `s2_tools.tools()` (2) + `s2_whatsapp.tools()` (1) + `activity.tools()` (1) = **22 tools**. S1 (`/next`) gets **all 22** (`sasha.tools_for_model()`, unfiltered). S2 (`/s2`) is filtered by `app/agent/s2.py` S2_TOOLS, which lists **the same 22 names**, so today S1 and S2 tool sets are identical.
- The yes machinery in S1/S2: `v0.explicit_yes` / `yes_to_book` / `yes_to_cancel` (AgAPI 1.1 AP6, sha-pinned lists), `s2_tools.strict_yes` (also vetoes questions), `READ_BACK_TTL_S = 900`, read-back must be from an EARLIER turn (`held["at"] < ctx.started`), durable `claim()` in basket_events for `ACTS = {book, book_venue, cancel_venue, send_email, send_whatsapp}`, idempotency_key required on Austen tools, `approval.said` filled from the real user message, never from the model.

## What is broken / in-flight

### HeyGen voice echo (active bug — awaiting HeyGen response)
**Symptom:** Occasionally Deepgram transcribes the avatar's own speech and triggers a premature response (the avatar "hears itself").

**Current mitigations in place:**
1. `micGatedRef = true` — PCM frames are dropped while avatar is speaking
2. 900ms trailing timer after `AVATAR_SPEAK_ENDED` before opening gate
3. Per-`repeat()` safety timer: `Math.max(1500, text.length * 65) + 900` ms — fallback if `AVATAR_SPEAK_ENDED` never arrives
4. `{ type: 'Finalize' }` sent to Deepgram on gate-open to flush buffered speech
5. Echo filter: 70% word-overlap check on transcripts vs `lastRepeatTextRef`
6. `isRespondingRef` lock in vietnam/page.tsx — blocks transcript processing while conductor is responding

**Status:** HeyGen support reviewed source code (repo is currently public for this). Waiting on their diagnosis. Do not change the gate architecture without understanding their response first.

## Voice pipeline — exact component responsibilities

```
vietnam/page.tsx
  ├── SashaAvatar (ref: avatarRef)
  │     SDK: LiveAvatarSession, voiceChat: false
  │     AVATAR_SPEAK_STARTED → onGate(true) + onAvatarSpeakingChange(true)
  │     AVATAR_SPEAK_ENDED   → 900ms → openGate() → onGate(false) + onReadyToListen() [once]
  │     speakFn: onGate(true) → avatar.repeat(text) → safety timer → openGate()
  │     interruptFn: avatar.interrupt() → clearTimers → onGate(false)
  │     keepAlive: every 150s
  │
  └── SashaChat
        ├── VoiceButton
        │     AudioContext → AudioWorkletNode (pcm-capture.js)
        │     micGatedRef=true at start; gate registered via onSetGate on mount
        │     while gated: measure RMS, drop frame (or interrupt if RMS > 0.0005)
        │     while open: float32→int16→ws.send → Deepgram
        │     Deepgram events: SpeechStarted, Results (is_final+speech_final), UtteranceEnd
        │     echo filter on finals → onTranscript(text) → sendMessage()
        │
        └── sendMessage() → POST /api/agents/conductor → response → onSashaResponse(text)
              onSashaResponse in vietnam/page.tsx → speakFnRef.current(text) → avatar.repeat()
```

### Gate prop chain (stable refs — critical)
```
vietnam/page.tsx:
  handleSetGate = useCallback((fn) => { gateRef.current = fn }, [])   // empty deps
  handleGate    = useCallback((value) => { gateRef.current?.(value) }, [])  // empty deps

SashaAvatar:  onGate={handleGate}
SashaChat:    onSetGate={handleSetGate}
VoiceButton:  registers gate in useEffect([], []) on mount
```
All three callbacks use `useCallback` with empty deps. **Do not inline these as arrow functions** — stale closures will break the gate silently.

## Rules — things that caused bugs before

1. `avatar.repeat(text)` — **one arg only**. No options object. Second arg causes silent failure.
2. `avatar.keepAlive()` — not `avatar.ping()`. Wrong name silently does nothing.
3. **Gate callbacks must use `useCallback` with empty deps** — inline arrow functions in the parent cause stale closures. Gate appears to register but never fires.
4. **Deepgram must not connect until after first `AVATAR_SPEAK_ENDED`** — use `onReadyToListen` → `voiceReady` state → `readyToListen` prop to delay `connect()`.
5. **`voiceChat: false` is mandatory** — `voiceChat: true` hands mic to HeyGen and breaks our pipeline.
6. **No auto-reconnect on Deepgram `ws.onclose`** — causes audio glitches. Let it close cleanly.
7. **Conductor timeout is 30s** — was 5s, silently killed every agent. Web search takes 8–15s.
8. **All agent tool loops use `claude-haiku-4-5`** — only conductor merge uses Sonnet. ~20x cost difference.
9. **Intent extraction uses triple-backtick JSON pattern** — `` r'```json\s*(.*?)\s*```' `` with `re.DOTALL`. Not a custom `JSONBLOCK` marker.
10. **`/public/pcm-capture.js` must exist** — VoiceButton loads it via `addModule('/pcm-capture.js')`. It exists. Do not delete it.
11. **Auth is fully removed from the frontend** — demo runs as hardcoded `DEMO_USER`. No Supabase auth on the client side.
12. **`AVATAR_SPEAK_STARTED` must gate the mic directly** — not just in `speakFn`. HeyGen's own LLM auto-greets on session start, bypassing `speakFn` entirely. The `AVATAR_SPEAK_STARTED` handler itself must call `onGate(true)`.
